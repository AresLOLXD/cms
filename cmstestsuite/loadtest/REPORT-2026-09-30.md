# Load test of main @ d3532b25 (condensed by the controller from the agent's hand-back)

Harness and raw results: this directory (compose.yml, run.sh, driver.py, monitor.py, analyze.py,
flushstats.py, lockwait.py, setup_contest.py, scenario.py, solutions/, out/{smoke,full1,full2,full3}/summary.md).

Scenario: 250 users (175 loada + 75 loadb), CMS_CONTEST_ID=ALL, two-phase on, GroupMin/Mul/Threshold,
depends_on chains up to 4 levels, 25-min contests, login burst, end burst; 16-core host, PG max_connections 100.

## Correctness
5,920 submissions in 4 runs: 0 HTTP errors, 0 stuck, 0 score mismatches, RWS == CMS for all 925 pairs,
250/250 logins, 0 WARNING/ERROR/Traceback in any service log. Peak PG connections 28/100.

## Runs
- full1 (8 workers, 2 CWS, realistic): login p50 0.215 s; submit p95 0.19 s (end burst); AC latency p50 16 s
  (no deps) to 53 s (4-level chain), max 75 s; last result 56 s after stop; CWS stalls up to 1.3 s at the stop.
- full2 (6 workers, 2 CWS, stress 1,203 subs in last 5 min): CWS stalls 6-7 s at the stop;
  26 submissions rejected silently (18 sent 0.5-4.3 s BEFORE the stop); queue 3,562; last result 306 s after stop.
- full3 (full2 with CMS_CWS_COUNT=4): 0 rejected; worst stall 0.3 s; last result 228 s after stop.

## Root causes
1. Request time is taken when the handler starts (cms/server/util.py:257), after the event-loop wait;
   CWS handlers run sync DB work on the loop; late requests are redirected silently (tasksubmission.py:83-87).
2. ES flush is debounced: flushes at 100 results or 2 s with no new result (flushingdict.py:169-172,
   EvaluationService.py:321-323) -> ~5 s per two-phase/dependency stage.
3. post_finish_lock held 0.6-3.9 s per flush; worker release waits on it (EvaluationService.py:923-970): 13-17 % capacity lost.
4. Capacity ~7.8 testcase jobs/s per worker on synthetic tasks.

## Ranked risks for 10-10
1. Last-second submissions silently rejected when CWS stalls. Now: CMS_CWS_COUNT=4, stop ~60 s after announced end.
   Later: timestamp on arrival / grace window; visible error.
2. Slow results for deep depends_on chains (~11 s per level). Now: avoid long chains. Later: max-age flush.
3. Backlog after the stop (1-5 min). Now: 8 workers; publish final ranking after the ES queue is empty.
4. ES lock contention. Later: release_worker before the lock; bulk-insert evaluations; per-result INFO -> DEBUG.
5. DB latency spikes freeze a CWS process (1.8-3.0 s commits seen). Check production disk latency.
6. Page polling backoff uncapped (1.2-1.5x perceived latency). Later: cap at 5-10 s.
"Found N missed operation(s)" near the stop is harmless.

## Limitations
One host, no nginx/TLS, synthetic cheap testcases, 25-min contests, one client IP.
