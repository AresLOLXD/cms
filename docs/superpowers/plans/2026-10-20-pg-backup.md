# Full-database backup and verify scripts (#60) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `backup.sh` that takes a consistent, restorable full copy of the CMS database with `pg_dump` 17+, a `verify-backup.sh` that proves a copy is restorable, and a documented restore procedure.

**Architecture:** A sourced shell library holds the pure helpers (URL parsing, version choice, names, manifest comparison) and is unit tested from Python like `docker/test_generate_config.py`. `backup.sh` and `verify-backup.sh` run `pg_dump`/`pg_restore`/`psql` inside throwaway `postgres:<major>` containers on the compose network, so nothing is installed on the host. Restoring is documented, not scripted.

**Tech Stack:** bash, Docker, PostgreSQL 16/17 client tools, pytest, Sphinx (docs and Spanish `.po`).

**Spec:** `docs/superpowers/specs/2026-10-14-pg-backup-restore-design.md` (scope approved by the user on 2026-10-20: no `restore.sh`). The spec decides; this plan fixes names, order and tests.

## Review Focus

1. A Ctrl+C, a failing `pg_dump` or a full disk leaves no `.partial` directory, no tool container and no open snapshot session. Pinned in Task 2.
2. A backup directory with a corrupted file, a missing large object or a wrong digest fails `verify-backup.sh` and names the failed check. Pinned in Task 3.
3. A database password with `@`, `%`, `:` or `/` in `CMS_DB_URL` parses correctly and never appears in argv, logs or the summary. Pinned in Task 1.
4. A label with a space, a slash or `..` is refused before anything is written (no escape from `backups/`). Pinned in Tasks 1 and 2.
5. Not enough free space for the dump stops before writing anything. Pinned in Task 2.

### Task 1: The shared library `docker/_backup_lib.sh`

**Files:**
- Create: `docker/_backup_lib.sh` (sourced, no side effects), `docker/test_backup_lib.py`
- Modify: `docker/_cms-test-internal.sh` (add the new test file to the docker group list), `.gitignore` and `.dockerignore` (add `backups/` beside `dumps/`)

**Interfaces (produces):** shell functions, all pure (no Docker call at source time):
- `parse_db_url URL` sets `PGHOST PGPORT PGUSER PGPASSWORD PGDATABASE`; accepts `postgresql://` and `postgresql+psycopg2://`, `%`-encoded user and password, an optional port (default 5432) and a `?query` suffix; fails with a clear message on an empty or malformed URL.
- `db_connection_from_env` sets the same variables: with `CMS_USE_LOCALDB=true` from `POSTGRES_USER/POSTGRES_PASSWORD/POSTGRES_DB` with host `db`, otherwise `parse_db_url "$CMS_DB_URL"`.
- `pick_pg_major SERVER_VERSION_NUM` prints `max(17, server major)` (`160015` gives 17, `170002` gives 17, `180001` gives 18).
- `backup_name [label]` prints `cms-YYYYmmdd-HHMMSS[-label]`; `label` must match `^[A-Za-z0-9_-]+$` or the function fails (no space, slash or `..`).
- `compose_network` prints the Docker network labelled with the compose project and `default`; it fails with `run ./up.sh first` when it does not exist. `pg_tool MAJOR CMD...` runs `CMD` in `docker run --rm --init --name cms-pgtool-$$ --network <compose network> -e PGHOST -e PGPORT -e PGUSER -e PGPASSWORD -e PGDATABASE postgres:MAJOR` (variable names only, the values come from the environment so they never appear in argv). Both call Docker only when invoked; they are exercised through the fake docker of Tasks 2 and 3.
- `manifest_compare A B` compares two count sections (`table<TAB>count` lines) and prints one line per mismatch or missing table; exit 0 only when identical.

### Task 3: `verify-backup.sh`

**Files:**
- Create: `verify-backup.sh`, `docker/test_verify_backup_sh.py`
- Modify: `docker/_cms-test-internal.sh`

**Interfaces:**
- Consumes: the library (`manifest_compare`), a backup directory as written by Task 2.
- Produces: `./verify-backup.sh <backup dir>`: needs only Docker, no `.env`. Steps of the spec: `sha256sum -c SHA256SUMS`; a throwaway `postgres:<dump major from MANIFEST>` container with an anonymous volume (a trap removes both, also on Ctrl+C); `pg_restore -j <nproc> --no-owner --no-acl --exit-on-error`; checks that fail on any mismatch: per-table and large object counts equal the manifest, every `fsobjects.loid` exists in `pg_largeobject_metadata`, zero rows where the SHA1 of the large object differs from `fsobjects.digest` (`pgcrypto` created in the throwaway database); orphan large objects are reported as information only. Exit 0 only when everything passes; otherwise non-zero and the failed check is named on stderr.
