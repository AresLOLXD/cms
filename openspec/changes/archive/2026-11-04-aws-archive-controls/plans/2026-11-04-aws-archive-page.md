## Group 1 (tasks 1.1-1.4)
- 1.1 `ARCHIVE_GRACE = timedelta(hours=24)` lives in `cms/db/rankinggroup.py` (with its comment); ProxyService does `from cms.db.rankinggroup import ARCHIVE_GRACE` (or via `cms.db`) and keeps using the name. Existing ProxyService tests must stay green.
- 1.2 `archive_at` is a time field of the group page, read in `read_ranking_group_visibility` with the exact `<name>_shown` stale rule, empty = None, malformed = ValueError (reuse the existing loop: iterate `WINDOW_FIELDS + (("archive_at", "Archive at"),)` for reading, but keep `check_window` and `visibility_view` fields for the four windows only). `visibility_view` returns the archive part: `archive_field` (name, label, utc), `archived_now` and a one-line `archive_summary` ("archivado desde ..." / "se archiva el ..." / "nunca se archiva", each with UTC and local time like `next_change`). The template shows the state, the field (same markup as the window fields, `data-utc-time`, hidden `_shown`) and the buttons.
- 1.3 `visibility_action` values `archive_now` (error "The group is already archived." when archived now; else `archive_at = now`) and `unarchive` (error "The group is not archived." when not archived now; else `archive_at = now + ARCHIVE_GRACE`). Buttons «Archivar ahora» (shown while not archived) and «Desarchivar» (shown while archived, with a `confirm()` saying that the whole group will be sent again). Like the other "now" buttons, the action replaces what is typed in the field.
- 1.4 In `RankingGroupHandler._post_sync`: `was_archived = group.is_archived_at(now)` before the edit, `now_archived` from the attrs after it (same `now`, one `make_datetime()` per request); after a successful commit, if `was_archived and not now_archived`, `schedule_rpc(proxy_service.regenerate_ranking, group=<name>)` after the existing `reinitialize`. The state is read after the `with_for_update` refresh. `get_attrs()/set_attrs()` must carry `archive_at` (check `RankingGroup` columns; Contest-style FK skipping does not apply).

## Group 2 (task 2.1)
- Rename refusal: in `_post_sync`, if the group is archived now (before the edit) and the submitted `name` differs from `group.name`, raise ValueError("Ranking group %r is archived: unarchive it before renaming it.") so the existing "Invalid field(s)" notification path shows it and nothing is saved.
- Contest refusal: in `ContestHandler._post_sync`, when the chosen group is not None, differs from `contest.ranking_group` and `is_archived_at(make_datetime())`, raise ValueError("Ranking group %r is archived: unarchive it before adding a contest.") before anything is set. The same group (even archived) is never refused. Tests in `contest_test.py` with the real DB.

## Group 3 (tasks 3.1-3.2)
- 3.1 In `BaseHandler.render_params`, when `self.contest` is not None and `self.contest.ranking_group` is archived at `params["timestamp"]`, set `params["archived_group"]` to the group. `base.html` renders, above the page content, a banner naming the group, saying that changes made there do not reach the public ranking until the group is unarchived, and linking to `url("ranking_group", group.id)`. Test the render params for the three Scenarios; add one rendered-template check if the existing tests have a cheap way, otherwise assert on the param.
- 3.2 `RegenerateRankingHandler._post_sync`: for a non-empty group name, load the group by name with `self.sql_session`; if it exists and `is_archived_at(make_datetime())`, do not schedule the RPC and add the notification "Ranking regeneration ignored" / "Ranking <name> is archived: nothing was sent. Unarchive it first to publish a correction." Everything else is unchanged. Update `TestRegenerateRankingHandler` for the session.
