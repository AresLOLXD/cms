## Conventions (all of them, from section 3)
1. Text nodes: `{% trans %}…{% endtrans %}`; variables as `{% trans name=expr %}…{{ name }}…{% endtrans %}` (no `{% if %}`, filters or attribute access inside; compute them in the trans args). Whole sentences, never fragments. Inline markup may sit in the msgid. Text with an apostrophe ALWAYS uses trans (`{{ _("…") }}` would emit `&#39;` and break raw-HTML tests).
2. Attributes (title, placeholder, alt, aria-label, value of UNNAMED submits): `{{ _("…") }}`. `{{ "…" }}` / `{% set x = "…" %}` literals that are shown become `_("…")`.
3. Whitespace-sensitive content (`<pre>`, `<textarea>` defaults): `{% trans notrimmed %}` or keep it out of the msgid. `trimmed` collapses newlines: check the rendered text equals today's (the English snapshot test does).
4. Plurals: `{% trans count=n %}…{{ count }}…{% pluralize %}…{% endtrans %}`; Python `self.n_(one, many, n) % {"count": n}`. When English does not inflect today, both English forms are identical so English stays the same. 0 takes the plural.
5. Python: `self._("…")` in handlers; always `self._("… %s") % x`, never `self._("… %s" % x)`; f-strings become `%` msgids (named placeholders when more than one); module-level texts `N_("…")` translated at use; module functions take a `gettext` parameter. No new render parameters (direct-render tests would break under StrictUndefined: build values in the template).
6. Notifications: `self.service.add_notification(make_datetime(), self._("Subject"), self._("Text") or repr(error))`. Stored in the actor's language (known limit, do not fix).
7. Errors: translate assert messages and the `ValueError`s we raise for the admin; KEEP `repr(error)`. Leave English: HTTPError reasons, logs, programmer errors, `cms/db`/`cms/grading` validation detail (translate only our prefix), library exception text, CSV header formats, the strings in the guard allow-list.
8. Operation identifiers: `<button type="submit" name="operation" value="<English as today>">{% trans %}<label>{% endtrans %}</button>`. NEVER translate a `value` a handler reads; an `<option>` with translated text gets an explicit English `value`. Keep every other attribute (`disabled` conditionals, `style`). Handlers compare against the same English constants as today.
9. Script texts: inline scripts with several messages use `{% set messages = {...} %}` + `data-messages="{{ messages|tojson|forceescape }}"` on the page container + the page's own `fill()`; a single literal: `{{ _("…")|tojson }}`; in event attributes `onclick="confirm({{ _("…")|tojson|forceescape }}) && …"`. `static/aws_utils.js` is L0 only (`CMS.AWSUtils.t`, fed from `base.html`). No JS i18n library, no plural engine beyond [one, many], no refactor of existing `fill()` copies.
10. Macros: imports always `with context` (done in P); a new import without it fails the guard.
11. Markers: when a file is complete add on its first line `{# aws-i18n: complete #}` (templates), `# aws-i18n: complete` (py), `// aws-i18n: complete` (js). Marking switches the guards strict for that file. Do NOT mark a file that still has English.
12.
