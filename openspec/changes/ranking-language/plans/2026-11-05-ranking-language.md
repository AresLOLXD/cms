## 1.1 `cmsranking/static/i18n.js` (new, plain script, no modules, no jQuery)
- Exposes `window.I18n = { lang, t(key), ... }`. Catalogs `{ es: {...}, en: {...} }` as a JS object literal: dotted lowercase keys (`label.status`, `time.elapsed`, `conn.reconnecting`, ...). English is the source text (copy the current strings EXACTLY); Spanish translations in the neutral register of the existing Spanish pages (e.g. Status -> Estado, Elapsed time -> Tiempo transcurrido, Remaining time -> Tiempo restante, Current time -> Hora actual, Show tasks -> Mostrar problemas, Totals only -> Solo totales, Search Team -> Buscar equipo, Score -> Puntaje, Rank -> Lugar, Name -> Nombre, Username -> Usuario, Team -> Equipo, Global -> Global, no submissions -> sin envíos, Yes/No -> Sí/No, Powered by CMS -> Con tecnología de CMS; the connection messages: translate faithfully and keep each `<a onclick=...>` markup inside the entry, same onclick code).
- Pick (design decision 2): `localStorage["cms.lang"]` equal to `es` or `en` (try/catch on every access; garbage means automatic); else scan `navigator.languages` (then `navigator.language`) in order and use the FIRST entry whose lowercase starts with `es` -> es; the first entry that starts with `en` -> en?? NO: keep the rule of the spec exactly: Spanish when the browser's preferred language (the first entry) starts with `es`, English in every other case. Set `document.documentElement.lang` and `data-lang` immediately (script runs in `<head>`).
- `t(key)`: current language text, else the English text, else the key. Static fill at DOMContentLoaded: elements with `data-i18n="key"` get `textContent`; `data-i18n-attr="alt:key,title:key,placeholder:key"` sets those attributes; `data-i18n-html="key"` (only for entries that keep markup) sets `innerHTML`. Also sets `document.title`? (the title is set by UserDetail.js later; the static `<title>` gets `data-i18n`-free handling: set it from key `title.ranking`).
- Language select: `select#language` (value = current language, not "automatic": show the resolved language); on `change` save to `cms.lang` and `location.reload()`.
- Header comment: purpose, the key, that the notice-page snippet in `cmsranking/visibility.py` must pick the language the same way (a test checks it). `node --check` clean; repo JS style (4 spaces, double quotes).
- `visibility.py`: add `"i18n.js": "pass"` to `FROZEN_ROUTES` (the existing test that every static top-level entry is listed must stay green).
- Tests (node harness like the theme one): Scenarios "Browser in Spanish" (navigator.languages ["es-MX"], no saved choice: lang es, data-lang es), "Browser in English or another language" (["en-US"], ["fr"], [] and undefined), saved choice beats the browser both ways, garbage saved value, throwing storage on read and write (no throw, browser language used), the select shows the resolved language and a change saves and reloads (stub `location.reload`), "Theme and language are independent" (the script never touches `cms.theme` / `data-theme`), `t` fallbacks, the static fill (stub DOM with data-i18n / data-i18n-attr elements), the frozen route (`test_visibility.py` style: served with the file's bytes when frozen).
